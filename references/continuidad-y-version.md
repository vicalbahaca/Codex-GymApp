# Continuidad entre dispositivos y versión

Versión del núcleo de seguimiento: **1.2.0** (12/11/2026).

## Identidad y disponibilidad

Usa el nombre y la versión del `SKILL.md` realmente cargado. Distingue una skill instalada, un archivo adjunto, una copia local y un repositorio. Un Markdown generado o guardado en la biblioteca no demuestra instalación. Tampoco la demuestra un commit ni una copia en `~/.codex/skills`.

Los paquetes para la cuenta deben incluir `SKILL.md` y todas sus referencias. Guardar el paquete en la cuenta e instalarlo son estados que hay que verificar por separado. No prometas sincronización automática entre el código de GitHub, las carpetas locales y la versión instalada en la cuenta: las actualizaciones deben guardar una nueva versión en cada destino utilizado.

Si se pregunta qué skill está activa, indica su identificador, versión y procedencia verificable. No inventes un nombre a partir de una conversación anterior. Si solo se dispone de un documento adjunto, dilo expresamente.

## Retomar el entrenamiento

El historial y el plan vigente se consultan en la hoja autorizada de Drive. No dependas de la memoria de otro chat ni de un archivo del ordenador para conocer la sesión actual. Conserva fecha real, semana, identificador de sesión, variante del ejercicio y series ya registradas; comprueba Drive antes de continuar o reintentar una escritura.

La skill aporta reglas y, en la variante privada, contexto personal. No concede permisos de Drive. Reutiliza la conexión ya autorizada cuando exista. Si el conector o la escritura no están disponibles en el dispositivo actual, explica la limitación y ofrece el registro pendiente sin presentarlo como guardado.

Usa las herramientas nativas de formularios si están disponibles y permiten el flujo solicitado. Si no, presenta una tabla breve o campos de respuesta en texto. No simules controles activos, temporizadores ni acciones guardadas. La falta de un formulario no debe bloquear una serie dictada o escrita por el usuario.

## Sustituir documentos anteriores

Mantén una sola lógica operativa por seguimiento. Los archivos anteriores sirven para recuperar preferencias o requisitos que el usuario quiera conservar; no son una segunda autoridad que fuerce otro flujo. Compara el contenido antes de declarar que no hay diferencias. Si no puedes leer un archivo completo, explicita esa limitación.

Prioriza la petición actual y los datos actuales verificados sobre supuestos de un documento antiguo. Ante una contradicción que cambie el plan, aclara solo lo necesario. No elimines archivos anteriores ni borres el historial para migrar. Usa el mismo registro de Drive y evita repetir escrituras al cambiar de skill o dispositivo.
